# Этапы разработки

Как запускать: новая облачная сессия Claude Code на ветке main этого репозитория,
сообщение одной строкой, например: «Выполни ЭТАП 1 из STAGES.md».
Один этап = одна сессия. Следующий этап — только после слияния (merge)
предыдущего в main. Общие правила работы — в CLAUDE.md.

---

## ЭТАП 1 — движок и каркас

Ты — опытный инди-разработчик. Мы делаем браузерную 2D-RPG «Один день в гимназии».
Это ЭТАП 1 из 6: движок и каркас.

Сначала прочитай целиком GAME_SPEC.md и JOKES.md. GAME_SPEC.md — единственный
источник правды, не меняй его. На этом этапе делай ТОЛЬКО то, что перечислено ниже.
Никаких уроков, карты школы и мини-игр — это следующие этапы.

ЗАДАЧИ
1. Создай в корне репозитория проект на Vite (чистый JS, без фреймворков) со
   структурой папок из раздела 19 спецификации. Подключи vite-plugin-singlefile.
   Команды: npm run dev — разработка, npm run build — один файл dist/index.html.
   Добавь .gitignore (node_modules и прочий мусор, но dist/index.html коммитится).
2. Движок (src/engine/): игровой цикл с фиксированным шагом 1/60; рендерер
   480×270 с целочисленным масштабом под окно и чёрными полями, пиксели без
   размытия, камера; ввод с клавиатуры по разделу 3 (pressed/held/released);
   менеджер сцен со стеком (push/pop/replace) и переходами-затемнениями;
   ГПСЧ с сидом (раздел 17); tween-утилиты; полный экран по F.
3. Битмап-шрифт по разделу 2: все глифы заданы в коде, кириллица включая
   Ёё Іі Ўў, латиница, цифры, знаки. Рисование строки с цветом, перенос по
   словам в заданную ширину, крупный режим ×2. Сцена-проверка, которая
   печатает весь алфавит (доступна из отладочного меню).
4. Генератор персонажей и портретов (src/gen/) по разделу 19: спрайты
   4 направления × 3 кадра, портреты 48×48 с эмоциями, кэш в offscreen-canvas.
   Заполни data/characters.js и data/teachers.js для ВСЕХ именных персонажей
   из разделов 9 и 10 (внешность, тон блипа, класс). Каждый должен узнаваться
   по силуэту: маллет Черняка, кудри Шурпо без бровей, очки Коли, нос Матыча,
   длинные кудри Игоря, рост Левончука и т. д. Сцена «Галерея»: все персонажи
   в ряд с именами и портреты во всех эмоциях.
5. Диалоги (src/ui/dialog, choice): окно в стиле Undertale по разделу 4,
   печать по буквам с блипами, пропуск, эффекты {shake}, меню выбора A–D.
   Парсер текстового формата диалогов из раздела 20 (метки, реплики, эффекты,
   выборы с условиями, переходы) с понятными ошибками по строкам.
6. Состояние игры (src/game/state.js) и data/balance.js со всеми числами из
   разделов 7, 8, 15. HUD по разделу 4: локация, время, 7 статусов иконками,
   мигание критических значений. Панель по Tab.
7. Звук (Web Audio): блипы с разным тоном, звуки меню, школьный звонок,
   свисток, удар, смех Игоря; простой секвенсор чиптюн-музыки из массивов нот
   и один трек для меню. M — выключить звук. Аудио — после первого нажатия.
8. Сохранение по разделу 18: localStorage в try/catch + код сохранения
   (экспорт/импорт, проверка контрольной суммы).
9. Главное меню и меню паузы по разделу 4 (пункты, которые ещё не работают,
   показывают «Скоро»).
10. Тестовая комната: тайловая карта 16×16 со стенами и коллизиями, Рома ходит
    и бегает (Shift), два NPC (Игорь и Черняк), с каждым можно поговорить по Z.
    Один диалог с выбором, который меняет статусы и видно изменение в HUD.
    Реплики — в data/dialogs/test.txt.
11. Отладочное меню (клавиша ` или ?debug): FPS, переход к сценам «Шрифт»,
    «Галерея», «Тестовая комната», изменение статусов. Архитектура такая,
    чтобы на следующих этапах сюда легко добавлялись уроки и мини-игры.

ПРОВЕРКА (обязательно, до того как сказать «готово»)
- npm run build проходит без ошибок, dist/index.html — один файл без внешних ссылок.
- Открой dist/index.html в headless-браузере (Playwright) через file://: в консоли
  нет ошибок, сделай скриншоты меню, сцены шрифта, галереи и тестовой комнаты
  с открытым диалогом. Посмотри на них сам: читаем ли текст, различаются
  ли персонажи. Исправь всё, что выглядит плохо.
- Проверь программно: парсер диалогов на тестовом файле; сохранение →
  код → загрузка даёт то же состояние; испорченный код не роняет игру.

ЗАВЕРШЕНИЕ — по правилам CLAUDE.md (сборка, скриншоты в docs/screenshots/etap-1/,
PROGRESS.md с картой модулей и ключевых API, коммит, пуш, короткий итог).
В коде нет TODO и заглушек, кроме пунктов меню «Скоро».

9. Деньги и ставки по разделу 8: общий модуль ставки (экран перед игрой)

11. Вейп вне мини-игр: действие «Затянуться» с последствиями из раздела 7.
    Срыв при стрессе 100 (тряска экрана, автопровал).

КАЧЕСТВО ТЕКСТА

  иногда ломанием четвёртой стены. Каждый друг звучит по-своему, фразы и

ЗАВЕРШЕНИЕ — по правилам CLAUDE.md (скриншоты в docs/screenshots/etap-2/,

## ЭТАП 4 — мини-игры

(Если этап не помещается в одну сессию: в первой сессии делай задачи 1–4,
во второй — «Выполни ЭТАП 4 из STAGES.md, задачи 1–4 уже сделаны, см. PROGRESS.md,

Это ЭТАП 4 из 6 игры «Один день в гимназии»: мини-игры.

Сначала прочитай GAME_SPEC.md (особенно разделы 7, 8, 14), JOKES.md и PROGRESS.md.
Все мини-игры реализуют единый интерфейс start/update/draw/end, регистрируются

ОБЩИЕ ТРЕБОВАНИЯ К КАЖДОЙ МИНИ-ИГРЕ

- 30–90 секунд, понятно с первого раза, сочная обратная связь (звук, тряска,
  частицы, всплывающие цифры).
- Учитывают голод > 70 (−20 %), срыв от стресса, игра идёт на ГПСЧ с сидом.
